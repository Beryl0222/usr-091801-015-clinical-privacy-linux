# 诊疗隐私用途管控

贯穿诊疗流程的隐私用途管控服务：电子病历访问、教学观摩、科研导出与现场影像的统一授权与留痕。针对“实习人员将未遮挡产科手术照片发到社交平台”类事件设计，用策略与审计替代口头提醒。

## 核心规则

- **访问三要素**：每次查看敏感记录必须携带患者关系（主治/分管/会诊）、业务目的（诊疗/紧急/教学/科研/传播）与最小字段范围；角色矩阵与 (角色, 用途) 字段上限之外的请求一律阻断。
- **知情同意绑定**：教学、科研、传播用途必须绑定患者知情同意的具体版本与有效期限，且同意覆盖请求的用途与字段；撤回后立即阻断尚未完成的导出（撤回与完成导出在同一把锁内串行化）。
- **break-glass**：紧急救治可短时解封（≤30 分钟），理由必填，授权与人员、患者绑定；到期自动失效，进入事后复核队列，并主动通知安全部门与患者门户。
- **水印与导出登记**：下载内容签发含操作者与时间的可验证水印（HMAC，支持密钥轮换，旧密钥保留用于验证）；系统不保存原始影像副本，只登记文件哈希、授权链（决策号 → 同意/紧急授权 → 会话号）与交付对象；同人同患者同哈希同交付对象的重复导出被阻断。
- **事件响应**：发现违规拍摄或外泄时可冻结相关审计（证据保全，哈希链保持完整）、按来源标识追踪同源导出、按保留政策发起删除确认（违规类立即到期，发起人与确认人必须不同）；审计日志仅追加，任何管理员都不能抹除自己的操作——抹除尝试会被拒绝并留痕。
- **决策缓存**：放行决策短 TTL 缓存，过期条目一律不采信，撤回时按患者主动失效。

## 目录结构

```
privacy/
  models.py      角色矩阵、字段上限、请求/决策模型、错误类型、通知中心
  audit.py       仅追加哈希链审计日志（冻结、拒绝抹除）
  consent.py     知情同意登记（版本、期限、范围、撤回监听）
  breakglass.py  紧急授权（理由、短时、复核、主动通知）
  policy.py      策略引擎与过期缓存
  watermark.py   水印签发/验证与密钥环轮换
  exports.py     导出会话与登记（只存哈希、授权链、交付对象）
  incidents.py   事件响应（冻结、同源追踪、删除确认、保留政策）
  facade.py      PrivacyService 门面（关键并发不变量）
  simulation.py  安全部门模拟场景
service.py       HTTP API 与入口（/health、/v1/*、--check、--simulate）
```

## 运行

```bash
python3 service.py --check        # 基础检查
python3 service.py --simulate     # 安全模拟：越权/过期缓存/重复导出/密钥轮换/并发撤回/break-glass/外泄处置
python3 service.py --port 8000    # 启动服务（GET /health，POST /v1/*）
npm test                          # 全部测试（契约 + 领域 + API）
```

## HTTP API 摘要

| 端点 | 说明 |
| --- | --- |
| `POST /v1/access/check` | 用途管控评估，返回放行/原因码 |
| `POST /v1/consents/register` · `/v1/consents/withdraw` | 登记/撤回知情同意 |
| `POST /v1/breakglass/request` · `/v1/breakglass/review` | 紧急授权与事后复核 |
| `POST /v1/exports/begin` · `/v1/exports/complete` · `/v1/exports/verify` | 导出会话、完成登记、水印验证（用文件哈希追授权链） |
| `POST /v1/incidents/report` · `/v1/incidents/trace` | 事件登记（冻结审计）、同源导出追踪 |
| `POST /v1/deletions/initiate` · `/v1/deletions/confirm` | 删除确认双人流程 |

错误映射：策略拒绝 403（携带原因码），同意撤回/重复导出/会话或删除状态冲突 409，请求非法 400。
